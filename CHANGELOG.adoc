==== Changed

* chore(repo): align the repository root to the `rsr-template-repo` allowlist and
adopt its shape gate (issue #109 item 1, ruling D186). `.machine_readable/
root-allow.txt` now records the root shape as law rather than as an accident, and
`scripts/check-root-shape.sh` (copied verbatim from the template) checks it
BIDIRECTIONALLY — an unlisted root entry fails, and a listed *required* entry that
is missing fails. Before this the repo had no allowlist at all, so the checker
exited 2 (setup error), which is how an unadopted gate reads as conformance for a
year. `tests/shape/check_root_shape_test.sh` — the template's own "prove the
instrument can fail" fixture — runs first, and `.github/workflows/estate-rules.yml`
gates both on every push and PR.

`ci/` (+ `ci/README.adoc`, which records the out-of-band GitLab project setting the
relocation needs), `manifest.scm` → `build/`, root `hooks/` → `.github/hooks/`,
`spec/SPEC.adoc` → `docs/SPEC.adoc`, and the root prose `AFFIRMATION.adoc`,
`ARCHITECTURE.adoc`, `EXPLAINME.adoc`, `GOVERNANCE.adoc`, `MAINTAINERS.adoc`,
`PALIMPSEST.adoc` → `docs/`. `.claude/CLAUDE.md` → root `CLAUDE.md`, where the
generator, pre-commit and Claude Code all look for it.

`SECURITY.md` (a pointer) + root `SECURITY.adoc` (a body that described
*SustainaBot*, not this project) became one `.github/SECURITY.md`; root
`MAINTAINERS` + root `MAINTAINERS.adoc` became `docs/MAINTAINERS.adoc`;
`CODE_OF_CONDUCT.adoc` became `.github/CODE_OF_CONDUCT.md`; the root `ROADMAP.adoc`

`contractiles/must/` path standards' checker defaults to — with its obligations

* `REUSE.toml` reduced to the files that cannot carry an in-file SPDX header. The
previous copy listed nine paths that no longer existed; REUSE does not complain
about an annotation whose target is gone, it just stops licensing anything, and

strictly in CI (`MUST_STRICT=1`, so a check skipped for a missing tool is a
failure rather than a pass). The file claimed "Run with: must check" for a `must`
binary that exists nowhere in the estate's reach, which is how its checks stayed
stale.
* `scripts/check-doc-links.sh` + `just check-doc-links`: every relative link in
the prose must resolve, with a `--self-test` that plants a dangling link and

==== Fixed

* `ci/.gitlab-ci.yml` declared a `trufflehog` job in `stage: security` while
`stages:` listed only `lint`/`test`/`build`. GitLab rejects that when *creating*
the pipeline, so every job in the file — `fmt`, `clippy`, `reuse lint`, unit tests,
doc tests, release build — had been dead, which is also why the REUSE drift above
was never reported. The stage list now matches the jobs; note that applying the
`ci/.gitlab-ci.yml` project setting is still required for the mirror pipeline to
run at all (see `ci/README.adoc`).
* `.github/CODEOWNERS` owned `SECURITY.md` (root) and `contractiles/` (never a
root path here) — two rules pointing at nothing. Now `.github/SECURITY.md`, plus
explicit ownership of the allowlist and the shape/lock/doc gates.
* `scripts/run-mustfile.sh` treated every unevaluated check as a critical failure
under `MUST_STRICT=1`, and its first CI run showed why that is wrong:
`signed-commits` is recorded in the contractile as *declared-unmet* (this repository
has no signing key), so a debt the contract had already priced as advisory turned the
gate red — reporting the state of the runner instead of the state of the repo. Strict
mode now makes an unevaluated check a violation at its declared severity, and each
failing check is also emitted as a `::error::` / `::warning::` annotation, because a
job whose only signal is `exit 1` costs somebody an hour of guessing.
* `.github/workflows/estate-rules.yml` provides `gawk` before the strict run.
`actions-lock-in-sync` is critical and `scripts/check-lock-sync.sh` needs awk's
3-argument `match()`, so an image without it would have failed the gate for an
ambient reason; the `- requires:` mechanism exists to make that dependency explicit,
and the CI step now honours it instead of hoping.

`Exemption ratchet`, so *adopting* it moved a count from 0 to 61 and the ratchet
asked for a declaration. The declaration is in the commit message
(`Ratchet-exception: .machine_readable/root-allow.txt — …`) rather than dodged by
prose-ising the entries: the ratchet counts non-comment lines, and rewriting real
entries as comments would disarm the one instrument that notices a root entry being
excused instead of minted.


==== Fixed

* fix(ci): remove the duplicate `+with:+` key in `+ci.yml+`. GitHub
rejects a workflow containing duplicate keys before creating any job —
the run is recorded `+failure+` with zero jobs, no log and no check run.
This is what the estate duplicate-key gate
(`+standards/scripts/check-workflow-duplicate-keys.sh+`, wired into the
Governance workflow) was failing on, and it had also been silently
killing the `+CI+` workflow on every push.
* fix(ci): reconcile `+actions.lock+` with the workflow YAML. Dependabot
#105 bumped `+github/codeql-action+` to v4.38.1 and
`+haskell-actions/setup+` to v2.12.1 in the workflows without
regenerating the lockfile. GitHub refuses a run whose `+uses:+` version
the lockfile does not record, at startup, with zero jobs — this is why
`+CodeQL Security Analysis+` and `+GitHub Pages+` went to
`+startup_failure+` on 2026-09-26 while reporting no log.
Both are held at the versions `+actions.lock+` already records —
`+haskell-actions/setup+` v2.12.0 and `+github/codeql-action+` v4.38.0 —
so the tree is self-consistent again. Re-landing the
`+haskell-actions/setup+` v2.12.1 bump requires regenerating the
lockfile with `+gh actions-lock+`
(`+standards/scripts/update-actions-lock.sh+`); that lockfile is
machine-generated and GitHub enforces it repo-wide, so it is not
hand-edited here.
* fix(ci): scan the SPDX header *block*, not line 1, in
`+workflow-linter.yml+` and `+hooks/validate-spdx.sh+`.
`+gh actions-lock+` prepends `+# This workflow is managed by gh
actions-lock.+` to every workflow it locks, displacing the SPDX line to
line 2, so the line-1 test reported all 17 workflows as unlicensed and
exited 17. Now matches the canonical form in
`+rsr-template-repo/.github/workflows/workflow-linter.yml+` and
`+standards+` `+governance-reusable.yml+`.
* chore(deps): hold `+github/codeql-action+` at v4.38.0 via a Dependabot
`+ignore+` rule, matching the estate-wide HOLD in
`+rsr-template-repo/.github/dependabot.yml+` — v4.38.1 fails GitHub
workflow-startup validation estate-wide, and a grouped bump cannot
regenerate `+actions.lock+`.
