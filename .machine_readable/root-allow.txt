# Canonical root allowlist for oikos-economics-accounting-dsl.
#
# Lists every entry permitted at the repository root. The check is
# BIDIRECTIONAL (see scripts/check-root-shape.sh, adopted verbatim from
# hyperpolymath/rsr-template-repo):
#   * anything at root that is not listed here is drift, and fails;
#   * anything listed here WITHOUT the '?' marker must exist, and its
#     absence fails.
#
# Provenance: this file is rsr-template-repo's `.machine_readable/root-allow.txt`
# aligned per RULING D186 (2026-09-30, on issue #109): "Align to the
# rsr-template-repo allowlist and remove the SECURITY/MAINTAINERS duplicates."
# Every deviation from the template's copy is marked below and carries a
# reason. Three kinds of deviation are admitted, and only these three:
#
#   MOVED     — the entry's canon home is a subdirectory, so this repo moved
#               the file rather than allowlisting it (`.gitlab-ci.yml` ->
#               `ci/`, `manifest.scm` -> `build/`, `hooks/` -> `.github/hooks/`,
#               root prose -> `docs/`).
#   TOOL      — a tool in this repo's toolchain reads the path from the root
#               and nowhere else (cargo, `reuse`, git). The entry is REQUIRED
#               because the tool is load-bearing here.
#   ABSENT-ON-RECORD — the template requires an entry this repo does not carry
#               and cannot honestly mint yet. It is marked '?' with the reason
#               and the blocking condition, never '?' merely to silence the
#               gate. Each such line names what has to happen for the '?' to
#               come off.
#
# The '?' marker's contract, inherited from the template and not relaxed here:
# mark an entry optional ONLY for template-only material removed at mint, for
# a module gated on a capability this repo does not declare (see
# .machine_readable/rsr-profile.a2ml and standards'
# template-capability-gates.toml), or for a debt with a stated unblocking
# condition. A one-directional allowlist only ever ratchets open; a
# '?' without a reason is the same failure in a different costume.
#
# Format
#   one entry per line; '#' starts a comment; trailing '/' marks a directory
#   '?' prefix -> OPTIONAL: permitted, but not required to exist
#
# ⚠ THIS FILE IS ALSO AN EXEMPTION LEDGER to hyperpolymath/standards'
# governance-reusable `Exemption ratchet`, which counts its non-comment lines and
# fails any pull request that grows the count without saying so. The entries below
# are therefore not free to add: a PR that adds one must carry, in a commit message
# or the PR body, a line of the form
#
#     Ratchet-exception: .machine_readable/root-allow.txt — <why this entry is owed>
#
# That is the mechanism the ratchet offers, and it is the one to use: renaming or
# reformatting this file to dodge the count (prose instead of entries, entries as
# comments) would silence the only instrument that notices a root entry being
# excused rather than minted. Issue #109 item 1 grew this ledger 0 -> 61 by
# ADOPTING the gate, and declared it rather than editing the file to fit.
